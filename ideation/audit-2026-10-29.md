## Choices made while building (for review)

- `DockerError` subclasses `EnvironmentLost` (rather than being mapped), so `build_image` failures are also
  `EnvironmentLost`; harmless, since setup catches every exception.
- `ConnectionError` and `TimeoutError` (Python built-ins) are retryable in the runner, next to `TransientError`.
- No cheap auth check in pre-flight: litellm has none that spends no tokens; only key presence is checked.
- Schema version 2 (the `workers` table): an existing `runs/harness.db` is refused; delete it (no migrations).
  (Now version 4: v3 phase times, v4 cost + time tracking, `database.md`.)
- `workspace.tar` is saved when the container is still up after the agent's turn; an unreadable workspace (e.g. the
  agent deleted it) is noted as a `workspace_saved` event with the error, not a failure.
- The #2 / #3 / #8 row is reconstructed from `database.md` #19 and the store/worker commits; the audit's original
  wording of those three findings isn't in the repo, so check which is which.
